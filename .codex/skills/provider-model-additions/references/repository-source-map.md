# autoshow-cli Repository Source Map

Use this checkout's runtime and CLI as the implementation baseline. Derive all inventory counts, defaults, service keys, and implementation status from the current autoshow-cli snapshot; do not carry them over from autoshow-bun reports.

The eight research workflows are `write`, `ocr`, `url`, `stt`, `image`, `video`, `music`, and `tts`. The CLI exposes writing through `write`, OCR/URL/STT through `extract`, and generation through `image`, `video`, `music`, and `tts`. Workflow labels, model-registry keys, CLI provider selectors, and adapter service keys are distinct; record their mapping rather than assuming they match.

Start with these repository sources, then follow their imports to the executing request and response code:

- **Shared model configuration:** `src/cli/commands/setup-and-utilities/models/`. `model-loader/registry.ts` loads the `llm`, `extract`, `stt`, `image`, `video`, `music`, and `tts` registries. Inspect `model-loader/paths.ts`, `model-loader/model-config-loader.ts`, and `model-loader/model-loader-schemas.ts` for config layout and validation. The `ocr-config/`, `stt-config/`, and `tts-config/` directories contain per-service JSON fragments; the other registries use `llm-config.json`, `image-config.json`, `video-config.json`, and `music-config.json`.
- **Selection and lifecycle:** Inspect the workflow `*-models.ts` files, `model-loader/defaults.ts`, and `model-loader/model-lifecycle.ts` alongside the configs. Include configured entries excluded from default selection or all-provider expansion. Treat `model-loader/retired-model-rates.ts` as historical accounting and migration context, not a list of currently selectable models.
- **Text/write:** `llm-config.json` and `llm-models.ts` under the model configuration directory; dispatch and adapters under `src/cli/commands/text/write/`, including `run-llm.ts` and `write-services/`.
- **OCR:** `ocr-config/` and `ocr-models.ts` under the model configuration directory; hosted lanes, local engines, and format extraction under `src/cli/commands/text/ocr/`. Inspect `ocr-utils/hosted-ocr-lane-registry.ts`, `ocr-engine-selection.ts`, and `ocr-local/` as well as provider adapters.
- **URL:** The URL entries in the shared `extract` registry, plus `src/cli/commands/text/url/url-provider-registry.ts`, `url-targets.ts`, `url-local/`, and `url-services/`. The `ocr-config/` directory also contains web-page extraction services; classify these as URL entries instead of counting them again as OCR. Include services with no selectable model and preserve any internal registry ID without presenting it as a provider model release.
- **STT:** `stt-config/` and `stt-models.ts` under the model configuration directory; dispatch in `src/cli/commands/stt/run-stt/dispatch.ts` and adapters under `src/cli/commands/stt/`. Transcript/caption retrieval belongs in the STT report even when its adapter lives under `src/cli/commands/text/url/url-services/`.
- **Image:** `image-config.json` and `image-models.ts` under the model configuration directory; `src/cli/commands/visuals/image/image-generation-targets/image-provider-registry.ts` and adapters under `src/cli/commands/visuals/image/image-generation-services/`.
- **Video:** `video-config.json` and `video-models.ts` under the model configuration directory; `src/cli/commands/visuals/video/video-targets/video-provider-registry.ts` and adapters under `src/cli/commands/visuals/video/video-services/`.
- **Music:** `music-config.json` and `music-models.ts` under the model configuration directory; `src/cli/commands/audio/music/music-targets/music-provider-registry.ts` and adapters under `src/cli/commands/audio/music/music-services/`.
- **TTS:** `tts-config/` and `tts-models.ts` under the model configuration directory; target collection in `src/cli/commands/audio/tts/tts-targets/tts-target-collect.ts`, serializers under `script-to-audio/`, and adapters under `tts-services/` in the same TTS directory. Keep endpoint, spoken text, inline delivery tags, and request-level instructions distinct when assessing capabilities.
- **CLI routing and provider names:** `src/cli/create-cli.ts`, `src/cli/commands/command-shared/extract-routing/provider-registry.ts`, `src/cli/commands/command-shared/generation-routing/generation-model-registry.ts`, and `src/cli/flags/service-selector-normalization/generic-provider-selectors.ts`.
- **Verification and prior evidence:** `package.json`, `test/test-runner.ts`, `test/test-runner/price-commands/`, and targeted contracts under `test/test-cases/validation/`. Consult `docs/reports/`, `docs/adr/`, and established `docs/benchmarks/` artifacts for dated context; their model lists and results do not override the current executing code.

Reconcile registry records with actual selection and dispatch. Identify local backends or service-only entries that execute without a model-registry record, and include them with an explicit no-model marker and source reference. Explain aliases and config/dispatch mismatches; do not silently omit hidden entries or inflate counts with CLI aliases, retired accounting records, or the same backend reached through multiple commands. Higher-level consumers such as comic generation do not create additional model tuples unless they select a distinct workflow/service/model combination.

For TTS, follow `tts-utils/tts-pricing.ts` and the model loader's `tts.ts` to distinguish published billing units from the units actually estimated. Inspect `script-to-audio/provider-serializer-registry.ts`, `tts-targets/multi-speaker-capability.ts`, and `src/cli/commands/audio/voice/` before recommending controls, native dialogue, or voice provisioning that may already exist. A local model selector can translate to a different wire ID or identify a service with no upstream model field; record that mapping explicitly. Use ADR-010 for lifecycle/version policy and ADR-012 for TTS/voice and retained-audio behavior.

Use repository-relative paths in report data and relative Markdown links from each report. Keep reports under `docs/reports/` and preserve established benchmark locations. Any necessary maintenance helper belongs under `src/tools/`, and test harnesses belong under `test/`; do not create Python files, a root-level `scripts/` directory, or any new root-level directory.
