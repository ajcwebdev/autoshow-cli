## Episode Summary

In this FS Jam solo episode without a guest, the hosts explore the surprisingly thorny process of building a third-party JavaScript script, as one host has been doing for Everfund's donation widget. They begin with how such scripts are written and bundled, tracing the history of module formats from CommonJS and AMD to ESM, and explaining why UMD remains the de facto output standard for scripts loaded onto other people's websites even though the UMD repository hasn't been updated since 2017 and ESM support now covers roughly 93% of browsers. This raises the business question of when it's acceptable to drop older browser support, given a script that must load 100% of the time on every customer site. They cover hosting approaches, contrasting private S3-backed scripts like Intercom and Canny with npm CDNs, and Everfund's choice to open source the code on npm. Architecture is next: whether to inject UI directly into the host page's DOM, as User Vitals does, or render inside an iframe, which Everfund chose because it avoids CORS issues and allows server-side updates without republishing the script, at the cost of harder CSS customization—prompting the question of why no startup has solved this problem and speculation about W3C portals as the future fix. They also discuss supporting frameworks like React, Vue, and Svelte, which led Everfund to split their SDK into a smaller core JavaScript version and a much larger React version, and recount debugging a WordPress-specific failure solved by bundling the script into the plugin itself. The episode closes with lighter topics: whether to build a headless donation SDK, the Divio documentation taxonomy of tutorials, how-to guides, reference, and explanation, Everfund's move to ReadMe.io, the upcoming Remix conference in Utah, potential sponsors and FS Jam merchandise, the ethics of endorsing products and vetting guests, parasocial relationships with listeners, favorite recent episodes on Hydrogen and Kent C. Dodds, and the goal of creating an evergreen historical record of web development.
