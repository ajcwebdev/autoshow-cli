# Benchmark Reports

This directory holds committed benchmark run data and the reports generated from it. The evidence lifecycle and paid-approval rules that governed these runs live in [ADR-015](../adr/ADR-015-govern-documentation-examples-and-verification-evidence.md). Pricing provenance, billing authority, and calibration promotion live in [ADR-010](../adr/ADR-010-hosted-model-registry-lifecycle-and-capability-policy.md).

## What this directory holds

- STT run directories under `stt/local`, `stt/with-speakers`, and `stt/without-speakers`; text run directories under `text/ocr`, `text/url`, and `text/write`; and the existing `tts`, `music`, and `video` roots. Each run keeps its canonical manifest, the retained provider artifacts, the consensus reference it was scored against, and its per-run comparison report. Audio, video, and image files are git-ignored, so runs that produced media keep only their metadata, hashes, and reports in the repository.
- The combined-report roots `text/ocr`, `stt/local`, `stt/with-speakers`, `stt/without-speakers`, and `text/url`. Each root holds `combined-comparison-report.json`, the data contract, and `combined-comparison-report.md`, the diffable text.
- The `tts` root, which has no combined report. Narration, emotion/delivery, and speed/pause benchmarks populate it when run. Controls use `tts/<YYYY-MM-DD>_05-tts-emotion/` and `tts/<YYYY-MM-DD>_06-tts-speed-pauses/`, dated when the benchmark first runs and pinned in the shared ledger for subsequent reuse. Each control benchmark selects its newest dated directory independently. An empty or absent root produces an empty TTS dashboard tab.
- Hand-authored `2026-05-21_combined-provider-comparison-report.md` files beside the `music` and `video` runs. Write preserves its September run and adds a pinned five-prompt benchmark with a [speed and cost report](text/write/benchmark-report.md), an executable input plan, canonical manifests, and per-run provider reports.
- One shared visual dashboard made of four generated files. `combined-comparison-dashboard.json` holds every tab's data: one tab per combined-report root, a TTS tab containing narration and both controls benchmarks, and a Write tab comparing the five selected prompts. `combined-comparison-dashboard.html` is a static shell that names that JSON, its stylesheet `combined-comparison-dashboard.css`, and its script `combined-comparison-dashboard.js` by relative name, and the script renders the JSON in the browser.

There is no CLI `benchmark` command. Reports are regenerated by the consensus skill from committed run data, and no runtime command, public flag, or execution API depends on this directory.

## Report architecture

The dashboard JSON is generated from the same data as the per-root JSON and Markdown, and the page holds no tables, metrics, or timestamps of its own. The script fetches the JSON and renders every tab, so the page needs JavaScript and an HTTP origin: browsers block a `file://` page from reading sibling files, and the page says so if it is opened that way. It has no third-party dependency. Sorting switches between three precomputed orders per group with CSS radios, and an optional control can rescore one group for a reader's own quality, speed, and cost preference. That preference is a viewing aid only: it is not saved, and the emitted JSON and Markdown stay free of composites, overall scores, and model tiers.

Reports rank price, speed, and quality within each provider group. Local, non-diarization, diarization, and other category groups are never combined into a cross-group overall leaderboard. Combined reports regenerate whenever a run is added, so the dashboard's four files are always generated together, never hand-authored.

The dashboard defaults to **Only CLI-supported models**. Its support snapshot comes from the current CLI selectors, dispatch adapters, and model lifecycle metadata when the dashboard is rebuilt. The toggle filters rankings, heatmaps, and evidence tables together; clear it to view every historical model. The browser remembers this choice, and switching views preserves the selected tab, sort order, and custom weights. Summary figures that cannot be recomputed from the retained evidence are labeled **Archive**. Saved benchmark reports, receipts, and costs retain their original models.

Earlier combined reports also assigned three contiguous quality-cost terciles per provider group under the method `quality-cost-terciles-v1`. That contract is retired: terciles were cohort-relative categories, not absolute quality labels, and live reports no longer emit tier membership or weighted composites.

## Five-prompt Write benchmark

The Write tab compares `shortSummary`, `longSummary`, `mediumChapters`, `blog`, and `rapSongChapter` across the 23 model/provider routes pinned in [benchmark-plan.json](text/write/benchmark-plan.json). Each prompt uses one fixed source across all routes, with one inference attempt per slot, two concurrent targets per provider, and existing CLI/model reasoning defaults, including low reasoning for direct Kimi K3. The runner preserves invalid outputs and failures and prevents automatic repurchase of attempted slots. Inspect the price-only plan with `bun src/tools/write-benchmark.ts --price`; the paid `--run` mode requires the repository's spending authorization.

The October 18 catalog cleanup first removed six selectors from active write/OCR selection, then removed all Kimi and GLM routes, including Together-hosted writing. This leaves 11 write routes and 21 hosted OCR routes. These saved benchmark results retain their original 23 write routes and costs; the dashboard's CLI-supported view excludes removed routes. The five Gemini 3.7 Flash receipts identify Gemini 3.8 Flash as the served model, so those two selectors represent the same served model in this batch. Verify the saved original receipts without dispatch using `bun src/tools/write-benchmark.ts --verify-cache`. Current `--price` output describes a new 55-slot plan with no inherited spending approval; it is separate from the saved historical plan.

Write speed uses observed seconds per request, and cost multiplies recorded provider usage by saved uncached catalog tariffs. Cache discounts and Gemini Argon introductory pricing are excluded, so these costs are not confirmed invoice charges. Each case has its own comparison, and the all-five aggregate includes only routes with valid artifacts for all five cases. Missing or invalid results remain visible, with recorded costs retained and unknown billing left unavailable. The September benchmark is preserved and excluded from this aggregate.

Targeted reruns use `bun src/tools/rerun-write-benchmark.ts --price` for a local estimate and `--prepare` to pin the seven unsuccessful first-pass slots in `text/write/rerun-plan.json`. The paid `--run` requires cost-specific approval and writes new attempts beneath each affected case's `reruns/02/` directory. It preserves the first pass and reuses existing rerun receipts without repurchasing them. The current comparison selects the latest completed attempt for each prompt/model pair; an unfinished rerun does not replace its earlier result. The report and dashboard retain every attempt's cost and unresolved billing, even after a later request succeeds.

At the user's explicit request, the Write tab uses output-token list price as a temporary quality proxy, labeled `Price proxy ($ / 1M output tokens)`, with higher prices sorting first. This is a model rate, separate from observed request cost and measured text quality. Automated and human quality surfaces in the standard per-run reports remain unavailable without assessment evidence. Other dashboard tabs retain their established quality metrics.

Regenerate the Write Markdown report with `bun src/tools/write-benchmark-report.ts --write`, then rebuild all four dashboard artifacts with the command below. Existing receipts are reusable benchmark state; preserve them with the purchased outputs.

## October 2026 OCR refresh

The 2026-10-17 refresh adds GPT-6.1 Sol, GPT-6 Luna, Claude Opus/Sonnet/Haiku 5.5, Gemini 4 Argon and Grok 4.7 to all thirteen established OCR inputs, covering 29 pages per model. Existing provider artifacts and recorded costs remain authoritative. The [combined comparison](text/ocr/combined-comparison-report.md) records the updated quality, speed and cost rankings.

The new models use their native default reasoning settings, provider concurrency 2 and page concurrency 1. Dashboard speed measures end-to-end provider processing, including credential-lane waiting and PDF preparation where recorded. Quality is the unweighted mean of per-input WER-derived scores; the ASCII word tokenizer does not measure Japanese glyph accuracy, so Unicode CER and source review remain necessary. Price uses recorded usage and registry tariffs rather than provider invoices; Gemini 4 Argon uses its conservative standard tariff. Failed requests without usage leave an unresolved billing amount and are excluded from successful-result rankings, with coverage reported separately.

For this refresh, plaintext `extraction.txt` exports have trailing spaces and tabs removed. The `result.json` artifacts retain the recorded provider text used for scoring.

## Compaction and regeneration

Compact a run only after trustworthy provider results exist. Preserve canonical result envelopes and historical identity, remove regenerable checkpoints, splits, and derived files only after validation, then regenerate the combined JSON and Markdown, then the dashboard, from those compacted artifacts. Finished artifacts keep the model identity they stored, and the cost recorded on a run remains the authority for that run.

From the repository root, the following command rewrites the dashboard's four files without provider calls. Running `build-combined-report` for any combined-report root reruns it automatically when all five combined-report roots are present.

```bash
bun .codex/skills/consensus/scripts/run.ts build-combined-dashboard
```
