# write

Generate structured LLM output from local markdown or plaintext. With no `--provider`, AutoShow selects the cheapest hosted LLM (currently `anthropic` / `claude-haiku-5-5`). Transcribe URLs, media, documents, or X Spaces with `extract` first, then pass the extracted `.txt` / `.md` to `write`.

## Usage

```bash
bun autoshow write <input> [flags]
```
`write` accepts local `.md` / `.txt` files or directories of those files. Empty files are rejected. A directly supplied file is also rejected as an input list when at least half its nonblank lines, excluding lines beginning with `#`, identify URLs, X Space ids, or existing paths. Directory inputs are scanned recursively. Use `bun autoshow write --help-topic providers` for selector details. Resume an existing write run with [`resume`](../00-setup-and-utilities/resume.md).

```bash
bun autoshow extract input/examples/video/01-two-speaker-speech.mp4 --provider deepgram --output-dir output/write-transcript
bun autoshow write output/write-transcript/transcription.txt --provider openai --prompt shortSummary --rendered-text
```
The second command uses the transcript generated by the first. See the [video fixture's license and provenance](../../../input/examples/video/README.md). Configure the selected providers' credentials and review `--price` before execution.

Project lyric draft mode uses a directory named `text` (for example `./output/<name>/text`) or a `.md` / `.txt` file under it, plus `prompt.md` in the parent directory (or an explicit `--prompt-file`). It reads that prompt, uses the adjacent `tracks.md` when present, and writes rendered Markdown drafts to the sibling `lyrics` directory. Explicit `--prompt-file`, `--track-list`, and `--rendered-out-dir` override those defaults.

## Shared Write Options

| Flag                                   | Description                                                                                                                                     |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `--provider <provider[=model]>`        | Select an LLM provider as `provider[=model]`; repeat to run multiple providers/models                                                           |
| `--all-providers`                      | Run every hosted LLM provider/model                                                                                                             |
| `--reasoning-effort <policy>`          | Set reasoning effort / thinking policy: `default`, `disabled`, `minimal`, `low`, `medium`, `high`, `xhigh`, or `max`                            |
| `--batch-limit <n\|all>`               | Limit batch size or process all items (`all`); default `5`                                                                                      |
| `--batch-order <newest\|oldest>`       | Use filename order (`newest`, default) or reverse filename order (`oldest`)                                                                     |
| `--batch-concurrency <n>`              | Batch items to process concurrently; default `7`                                                                                                |
| `--provider-concurrency <n>`           | Hosted providers/models to run concurrently per write item; default `7`                                                                         |
| `--concurrency-mode <ramp\|immediate>` | Ramp from one request (`ramp`, default) or start at the configured cap (`immediate`)                                                            |
| `--prompt <name...>`                   | Select prompt presets                                                                                                                           |
| `--prompt-file <file>`                 | Prepend instructions from a local text file before named prompt presets                                                                         |
| `--rendered-text`                      | Save rendered markdown output inside the run directory                                                                                          |
| `--rendered-out-dir <dir>`             | Also write rendered markdown files to this directory                                                                                            |
| `--track-list <file>`                  | Optional `tracks.md` file used to prepend track-number headers on saved rendered text                                                           |
| `--prompt-md`                          | Save a second prompt file (`prompt-md.md`) with markdown examples alongside the JSON prompt                                                     |
| `--price`                              | Show the aggregated estimate and exit                                                                                                           |
| `--max-model-cents <n>`                | Exclude each provider/model whose estimated total across the invocation exceeds the per-model ceiling in cents; works with or without `--price` |

List current prompt presets with `bun autoshow write --help-topic prompts`.

See [Provider Capabilities](#provider-capabilities) for the per-model reasoning, context, structured-output, and input/output price matrix.

```bash
bun autoshow write output/write-transcript/transcription.txt --provider openai=gpt-6.1-sol --prompt shortSummary longSummary
bun autoshow write input/examples/document/harborlight-field-notes.md --provider openai=gpt-6.1-sol --prompt blog
bun autoshow write input/examples/tts/harborlight-chapters --prompt rockSong
bun autoshow write input/examples/tts/harborlight-chapters --prompt rockSong --price
bun autoshow write input/examples/tts/harborlight-chapters --prompt rockSong --all-providers --max-model-cents 50 --price
```
The Harborlight field notes support a camping-story blog adaptation; `rockSong` adapts each chapter in the text batch into lyrics.

Write `--price` estimates use the selected prompt and source text. Use `--json` for structured token estimates and rates.

`--max-model-cents` is a selection filter, not a total command budget. For directory and batch inputs, AutoShow sums each provider/model's estimates across the selected inputs before applying the ceiling. Without `--price`, only retained targets execute. Use the configured `maxCents` budget from `setup --max-cents` when the combined cost of all retained targets must stay below a command-wide limit.

## Write Services

`--provider` accepts `provider[=model]`. Omitting the model uses the cheapest supported model for that provider. Headline per-1M rates are in [Provider Capabilities](#provider-capabilities).

`--all-providers` selects all 12 active write models. The four frontier additions are write models only; their IDs are not accepted by OCR or STT. Retired model names fail locally; where a replacement is recorded, the error names it. Claude Haiku 5.5 and GPT-6 Luna tie at the lowest headline rates; omitting the provider selects Anthropic.

| Provider  | Selector                         | Default model      |
| --------- | -------------------------------- | ------------------ |
| OpenAI    | `--provider openai[=<model>]`    | `gpt-6-luna`       |
| Anthropic | `--provider anthropic[=<model>]` | `claude-haiku-5-5` |
| Gemini    | `--provider gemini[=<model>]`    | `gemini-3.8-flash` |
| Grok      | `--provider grok[=<model>]`      | `grok-4.7`         |

### OpenAI

```bash
bun autoshow write input/examples/document/harborlight-field-notes.md --provider openai=gpt-6-astra --prompt shortSummary --reasoning-effort high
bun autoshow write input/examples/document/harborlight-field-notes.md --provider openai=gpt-6.1-terra --prompt shortSummary --reasoning-effort disabled
bun autoshow write input/examples/document/harborlight-field-notes.md --provider openai=gpt-6.1-sol --prompt shortSummary --reasoning-effort high
bun autoshow write input/examples/document/harborlight-field-notes.md --provider openai=gpt-6-luna --prompt shortSummary --reasoning-effort disabled
```
GPT-6 Astra, GPT-6.1 Terra, GPT-6.1 Sol, and GPT-6 Luna accept `low`, `medium`, `high`, `xhigh`, and `max`; all reject `minimal`. Astra and Sol require reasoning and reject `disabled`. Terra and Luna accept `disabled`, serialized as native `reasoning.effort: "none"`. Omitted effort and explicit `default` remove the override and delegate to provider defaults; Terra, Sol, and Luna default to `medium`. Requests use Responses and native `text.format` JSON schema output without unsupported sampling controls. [Astra](https://developers.openai.com/api/docs/models/gpt-6-astra), [Terra](https://developers.openai.com/api/docs/models/gpt-6.1-terra), [Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [Luna](https://developers.openai.com/api/docs/models/gpt-6-luna).

All four have a 1,050,000-token context and 128,000-token provider maximum output. Astra and Terra have a separate 922,000-token maximum input; context size does not increase that input allowance. See the [migration guidance](https://developers.openai.com/api/docs/guides/latest-model/gpt-6-astra.md#migration-quickstart).

The base rates in the capability table apply through 272,000 input tokens. At 272,001 or more, the entire request reprices: Astra `$20 / $75`, Terra `$2 / $7.50`, Sol `$4 / $15`, and Luna `$0.20 / $0.75` per 1M input/output tokens. Cached-input rates also double: Astra `$2` and Terra `$0.10` per 1M. Published 30-minute/12-hour cache-write rates are `$12.50 / $25` for Astra and `$1.25 / $2.50` for Terra before the long-context multiplier. These caching rates are provenance metadata; write does not request explicit caching. The new models use uncalibrated timing estimates. [Pricing](https://developers.openai.com/api/docs/pricing).

### Anthropic

```bash
bun autoshow write input/examples/document/harborlight-field-notes.md --provider anthropic=claude-fable-5-2 --prompt shortSummary --reasoning-effort high
bun autoshow write input/examples/document/harborlight-field-notes.md --provider anthropic=claude-opus-5-5 --prompt shortSummary --reasoning-effort medium
bun autoshow write input/examples/document/harborlight-field-notes.md --provider anthropic=claude-sonnet-5-5 --prompt shortSummary --reasoning-effort high
bun autoshow write input/examples/document/harborlight-field-notes.md --provider anthropic=claude-haiku-5-5 --prompt shortSummary --reasoning-effort disabled
```
Claude Opus, Sonnet and Haiku 5.5 accept `low`, `medium`, `high`, `xhigh`, and `max`; all reject `minimal`. Opus and Sonnet reject `disabled`; Haiku accepts it. Omitted effort or `default` uses `medium` for Opus/Haiku and `high` for Sonnet. All have a 1M-token context; AutoShow caps each write response's thinking plus text at 16,000 tokens. [Opus](https://platform.claude.com/docs/en/models/opus-5-5/overview), [Sonnet](https://platform.claude.com/docs/en/models/sonnet-5-5/overview), [Haiku](https://platform.claude.com/docs/en/models/haiku-5-5/overview).

Haiku 5.5 uses `$0.10 / $0.50` per 1M input/output tokens through 100,000 prompt tokens. Above that threshold, its entire request, including output, uses `$0.50 / $2.50`. Opus 5.5 uses `$4.00 / $20.00`; Sonnet 5.5 uses `$2.00 / $10.00`. [Pricing](https://platform.claude.com/docs/en/about-claude/pricing).

Claude Fable 5.2 also accepts `low`, `medium`, `high`, `xhigh`, and `max`, and rejects `minimal` and `disabled`. Adaptive thinking is always enabled: AutoShow omits `thinking` and sends an explicit effort only through `output_config.effort`; omitted effort or `default` delegates to native `high`. Its 1,000,000-token context and 128,000-token provider maximum output are distinct from AutoShow's unchanged 16,000-token application budget for thinking plus text. Rates are `$8 / $0.20 / $40` per 1M input/cached-input/output tokens across the full context window, without long-context bands. Its timing estimate is uncalibrated. [Fable specifications](https://platform.claude.com/docs/en/models/fable-5-2/overview).

Fable 5.2 requires 30-day retention unless Anthropic expressly authorizes zero data retention. Native structured output is unavailable in CMEK organizations. AutoShow preserves those provider errors: it does not substitute a model or remove `output_config.format` schema enforcement. Adding Fable 5.2 does not restore Fable 5 or 5.1. [Migration requirements](https://platform.claude.com/docs/en/models/fable-5-2/migration-guide).

### Gemini

Gemini 3.8 Flash accepts `--reasoning-effort low`, `medium`, or `high`; `minimal` and `disabled` are rejected. Its `--price` estimates use the standard `$1.50 / $7.50` rates that take effect 2027-01-01, so they overstate cost during the introductory `$0.75 / $3.75` window through 2026-12-31.

```bash
bun autoshow write input/examples/document/harborlight-field-notes.md --provider gemini=gemini-4-argon --prompt shortSummary --reasoning-effort medium
bun autoshow write input/examples/document/harborlight-field-notes.md --provider gemini=gemini-4-carbon --prompt shortSummary --reasoning-effort high
```
Gemini 4 Argon and Gemini 4 Carbon accept `low`, `medium`, and `high`, serialized as `LOW`, `MEDIUM`, and `HIGH`. Omitted effort or `default` removes the override and delegates to native `medium`. `disabled`, `minimal`, `xhigh`, `max`, numeric thinking budgets, and unsupported sampling controls are rejected before dispatch. Carbon candidate-count overrides are unsupported; Argon retains its existing behavior. [Argon](https://aistudio.google.com/docs/models/gemini-4-argon), [Carbon](https://aistudio.google.com/docs/models/gemini-4-carbon).

Both use a unified 1,048,576-token window shared by input, thinking, and output. AutoShow calls direct, non-streaming REST `generateContent` and limits thinking plus output to 32,768 tokens. The 65,536-token figure applies to streaming or SDK invocation modes; existing Flash OCR retains its separate 65,536-token cap. AutoShow rejects truncated, continuation, missing-candidate, and thinking-only responses, retains raw evidence, and does not automatically continue or redispatch. [REST limits](https://aistudio.google.com/docs/long-decode?generate-content=true#default-output-limits).

Carbon requests `POST https://generativelanguage.googleapis.com/v1beta/models/gemini-4-carbon:generateContent` with native `generationConfig.responseFormat.text` containing `mimeType: "APPLICATION_JSON"` and the schema. Argon and Flash retain their existing schema serialization. [Structured output](https://aistudio.google.com/docs/structured-output?generate-content=true).

Both Gemini 4 models conservatively use `$4 / $0.20 / $20` per 1M input/cached-input/output tokens, overstating introductory `$2 / $0.10 / $10` rates through 2026-11-30. Standard rates begin 2026-12-01. Output pricing includes thinking tokens, counted once. Explicit caching and automatic date-based tariff changes are unsupported; Carbon timing is uncalibrated. [Carbon pricing](https://aistudio.google.com/docs/pricing#gemini-4-carbon), [Argon pricing](https://aistudio.google.com/docs/pricing#gemini-4-argon).

### Grok

```bash
bun autoshow write input/examples/document/harborlight-field-notes.md --provider grok=grok-4.7 --prompt shortSummary --reasoning-effort high
```
Grok 4.7 has a 500,000-token context. It accepts `low`, `medium`, `high`, and `xhigh`; omitted effort or `default` uses `high`. Reasoning cannot be disabled; `minimal` and `max` are rejected. Its write requests use the provider's default limit of 128,000 visible output tokens, separate from reasoning tokens. [Model](https://docs.x.ai/developers/models/grok-4.7), [output limits](https://docs.x.ai/developers/model-capabilities/legacy/chat-completions).

Grok 4.7 costs `$2 / $6` per 1M input/output tokens below 200,000 input tokens. At 200,000 or more, its entire request uses `$4 / $12`. [Pricing](https://docs.x.ai/developers/pricing).

### Research

- `sources`: Extract a deduplicated, relevance-ranked inventory of concrete works, official records, and personal accounts discussed in the input. Each record includes its name, stated creator (or `null`), type, exact first-reference timestamp or location, context, and identification confidence. Return an empty source list when none are identifiable.
- `literatureReview`: Synthesize the supplied material into an academic review with thematic evidence, theoretical frameworks, methodological analysis, critical evaluation, research gaps, future directions, and references. State evidence limits and leave unsupported lists empty.

Both prompts use only the supplied input. They do not browse for references or verify external sources, and they must not invent authors, publication dates, URLs, citation details, or research findings.

```bash
bun autoshow write input/examples/document/harborlight-field-notes.md --prompt sources --rendered-text
bun autoshow write input/examples/document/harborlight-field-notes.md --prompt literatureReview --rendered-text
bun autoshow write input/examples/document/harborlight-field-notes.md --prompt sources literatureReview --price
```

Single-prompt output is the task's JSON object. Combined selection returns separate `sources` and `literatureReview` objects keyed by prompt name; the `sources` object contains its own `sources` array. `--rendered-text` also saves readable Markdown, and `--price` estimates without generation.

### Song Explainer

`songExplainer` builds a listening guide explaining the terms, people, places, objects, events, relationships, allusions, metaphors, and other context needed to understand each lyric. It accepts three input types:

- **Source text only:** A transcript, book chapter, article, or other general text. Produces background and a glossary for a song adapted from that material, explicitly noting that no lyrics were supplied. It does not invent lyrics or line annotations.
- **Lyrics only:** Explains every supplied lyric in order, with a glossary and relevant background. Identifies ambiguity and missing source context.
- **Lyrics and original source:** Connects individual lyrics to the original material, resolves compressed references, and flags meaningful changes, unsupported additions, or contradictions.

```bash
bun autoshow write input/examples/document/harborlight-field-notes.md --prompt songExplainer --rendered-text
bun autoshow write output/<song-write-run>/text.md --prompt songExplainer --rendered-text
bun autoshow write input/song-context.md --prompt songExplainer --rendered-text
```

For paired input, put both parts in one `.md` or `.txt` file, with clear labels. For example, save this as `input/song-context.md`:

```markdown
## Lyrics

### Verse 1
Mara lets the tide ledger speak
She lifts the gate so the quay can breathe

## Original source

Mara is the lockkeeper at North Quay. She checks the tide ledger, a record of water levels, before opening the harbor gate. Boats return after she opens it.
```

Lyrics may be plain text, rendered Markdown, or a structured song object pasted into the input document. For recordings or documents, run `extract` first and pass the resulting text to `write`.

Output identifies the input type and includes background, a glossary, lyric annotations and uncertainties. Glossary entries distinguish supplied evidence, general knowledge, interpretation and unresolved references. Annotations preserve lyric order and repeated choruses, using global line numbers that exclude headings, stage directions and blanks. Source-only input has no lyric annotations; lyrics-only annotations have no source connections.

`--rendered-text` saves a readable Markdown guide alongside the JSON. Add `--price` to estimate before generation. The prompt does not browse or claim external verification. Multiple selected prompts share the same input; to explain newly generated lyrics, pass their saved output to a subsequent `write --prompt songExplainer` run.

## Output

- `write` output is JSON by default.
- Single-target runs write `text.json` and `show-note.md`.
- Multi-target runs write `text-<model>.json` and `show-note-<model>.md` for each selected LLM target. When two providers share a model id, the filename includes the provider.
- `--rendered-text` writes rendered markdown inside the run directory: `text.md` for a single target, or `text-<model>.md` per model when multiple targets are selected. A shared model id uses the same provider-prefixed stem as the JSON file.
- Runs also write `prompt.md` and `manifest.json`. `--prompt-md` adds `prompt-md.md` with markdown examples alongside the JSON prompt.

## Generate Media from Write Output

`write` stops after text generation. Generate speech, images, video, or music from rendered markdown:

```bash
bun autoshow tts output/<write-run>/text.md --provider elevenlabs
bun autoshow music output/<write-run>/text.md --provider elevenlabs
bun autoshow image "$(cat output/<write-run>/text.md)" --provider openai
bun autoshow video "$(cat output/<write-run>/text.md)" --provider grok
```
Lyric drafts pair with `music --lyrics-file`.
