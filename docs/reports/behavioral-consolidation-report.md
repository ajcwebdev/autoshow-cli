# Behavioral Consolidation Plan

Date: 2026-08-09. Scope: entire repository at the current working tree on `staging` (uncommitted waves 28–35 included). This plan is the companion to `duplication-report.md` and implements the behavioral-consolidation program as a series of waves and subwaves: Wave 1 fixes every live bug the analysis surfaced (one subwave per bug, small direct diffs), then Waves 2–6 implement the 31 consolidation findings grouped by ascending migration risk (one subwave per finding). Finding IDs (BC-N) are stable and non-contiguous — the program was narrowed from 48 verified findings to 31 in review, and the cut findings' bugs live on as Wave 1 subwaves marked "standalone".

Provenance, condensed: every finding below was produced by one of eleven subsystem analysts (plus a completeness critic) and then re-verified by an independent adversarial verifier that re-read every citation, re-counted every line, diffed allegedly-identical regions, and grepped `test/` for assertions pinning current behavior. All nets are the VERIFIER'S corrected figures (`lines deleted − new engine/adapter/type/import lines`). Full method notes are at the end. Line anchors reference the working tree of 2026-08-09 and WILL drift — re-read every site before extracting, and if two copies differ where this plan calls them identical, surface it as a divergence rather than unifying.

## How to execute a subwave

Every subwave lands `bun run check` clean plus the local test suites named in its text; never run paid or quota-limited e2e suites as verification. Where a subwave names a differential harness (mock-fetch replay, fixture byte-diff, argv corpus), build it BEFORE migrating, not after. The calibration rule inherited from the mechanical report applies throughout: extract-a-new-engine estimates miss, adopt-and-delete estimates beat. Subwaves within a wave are ordered for execution (dependencies noted inline); waves themselves are risk bands, so a later wave may be started before an earlier one finishes except where a dependency note says otherwise.

## Wave 1 — live-bug fixes (one subwave per bug)

Direct, minimal fixes. Where a later consolidation subsumes the fix structurally, the subwave says so; landing the direct fix first is always acceptable, and for W1.4/W1.6 the noted consolidation is the cheaper vehicle if it is scheduled soon.

### W1.1 — HappyScribe STT double-billing window

`run-happyscribe-stt.ts:350` persists a non-resumable 'completed'-stage runtime BEFORE transcript/export retrieval; a crash during export makes the retry re-create a paid order. Fix: move the 'completed' persist after successful transcript/export retrieval so the runtime stays 'polling' (resumable) until the result is in hand. Verify with a mock-fetch replay of the crash-during-export path (the `audio-stt-contracts.test.ts` pattern). Made structural by W5.1, whose engine ordering cannot express the bug.

### W1.2 — Soniox STT deletes remote resources on retryable failures (gated: ruling 1)

`run-soniox-stt.ts:263-268` deletes the remote transcription AND file unconditionally in `finally`, even on a retryable poll-deadline failure while the on-disk checkpoint still says 'polling' — resume then polls a deleted job (404). Fix: gate both deletes on a terminal outcome (finished/failed), matching rev/speechmatics. Subsumed by W5.1's `cleanup.shouldDelete(ctx)` hook.

### W1.3 — OCR rendered-page pool keeps issuing paid requests after a page fails

`page-concurrency.ts` `runOrderedOcrPageTasks` has no early stop: the first failure rejects `Promise.all` while surviving workers keep running — with the preparation cache enabled they keep issuing paid kimi/grok/deepinfra requests for remaining pages against an already-deleted temp dir. Fix: add a stop-scheduling flag checked before each task starts (pipeline B's semantics). Covered by the local mock in `rendered-hosted-pages.test.ts`. The pool is deleted outright by W6.1.

### W1.4 — `bun autoshow write <media>` silently ignores 48 option keys

`media-runner.ts:48-240` never forwards 48 keys present in both RuntimeOptions and ProcessingOptionsSchema (every STT provider added after the ladder was written — happyscribe, supadata, scrapecreators, gemini, together, whisperfile — plus fal image, replicate/lumalabs/fal video, concurrency options, promptMd, configPath), so `collectSttTargets` at `process-video.ts:55` sees undefined. Direct fix: append the missing forwards to the ladder. Preferred vehicle: land W3.12 (BC-24) instead — its phase 2 IS this fix, with a compile-time completeness gate so the class of bug becomes unrepresentable.

### W1.5 — Gemini write requests are unbounded and uncancellable

`run-gemini.ts` sets no `timeoutMs` in its withRetry context, ignores the signal parameter, and never passes `geminiGenerateContent`'s supported `abortSignal` — a hung socket hangs the write step indefinitely where every sibling caps at 30 minutes. Fix: wire `AbortSignal.timeout(LLM_REQUEST_TIMEOUT_MS)` (combined with the retry signal) into the gemini call. No test asserts fetch signal presence, so `gemini-rest-contracts.test.ts` stays green. Made structural by W3.9.

### W1.6 — No polled generation runner retries create or poll (gated: retry-policy decision)

`pollUntil` has no error handling, so a single transient 500 mid-poll aborts a paid in-flight generation in all 8 hand-rolled image/video runners — violating the retry-on-any-error convention that replicate/fal/minimax-TTS follow. Direct fix: wrap each runner's poll (and optionally create) fetch in `withRetry(runtime_http_read)` (~6 lines × 8 runners). Preferred vehicle: W4.4 (BC-8), where retry policy becomes a single engine decision instead of eight hand edits.

### W1.7 — MiniMax video/music failures mislabeled as TTS errors

`minimax-utils.ts` hardcodes stage `'tts:minimax'` at lines 14/21/26 while video and music import its helpers. Fix: add a stage parameter to `ensureMinimaxBaseRespSuccess`/`parseMinimaxJsonResponse` and pass `'video:minimax'`/`'music:minimax'` from those runners. Contract suites (deepgram-minimax, minimax-video, music-provider-contracts) cover all three flows. Subsumed by W3.8, which relocates the module.

### W1.8 — `fal` missing from run-video-gen's provider list

`run-video-gen.ts:52` omits `fal[=model]` from the usage-error provider list that its twin check at `define-video-command.ts:203` includes — users on that path are told fal does not exist. Fix: add fal to the runtime-path string; align the music twins' trailing-period difference while there. One-line fixes; standalone (the command-tail consolidation was cut from the program).

### W1.9 — Video/music usage errors name flags users cannot type

`replicate-video-targets.ts:58-157` CLIUsageErrors and the minimax/gemini music runners' warnings name internal `--video-*`/`--music-*` spellings those commands do not register; only the image command got `retargetUsageErrorToCommandSpellings` (with its own contract test). Fix: generalize the retargeting wrapper to video and music, keyed by each command's option-name map (~10 added lines — a fix, not a dedup). Standalone. The runtime `l.warn` messages below the command layer need their spellings updated directly.

### W1.10 — STT resume manifests never advance attempts; root artifactDir rewritten (gated: ruling 8)

`stt-run-state.ts:492/503/522` record `existing ?? 0` in every branch (OCR increments on failure and defaults success to 1) — attempts counters are permanently frozen; and the success branch hardcodes `providers/<dir>` even for successes resumed from the run root, recording a directory containing no artifacts (OCR preserves `success.relativeDir`). ### W1.11 — OCR resume can report 'full' with a requested provider missing (gated: ruling 8)

### W1.12 — URL resume: stale batch.json, skipped sync, success-on-failed-run

### W1.13 — OCR checkpoint manifests drop four failure-diagnostic fields

The checkpoint pick-map at `ocr-multi-provider-batch.ts:74-85` keeps 10 fields where finalize (242-257) keeps 14, dropping `stage`/`status`/`retryAfterMs`/`rawResponseFile` (old report divergence #2, re-verified). ### W1.15 — Retry-After silently discarded at four attach sites

`elevenlabs-ivc.ts:129-131`, `dl-audio.ts:114-116` and `:186-188`, and `setup-download/download.ts:225-228` attach `.status` without `.headers`, so `classifyFetchRetry` loses Retry-After pacing on those paths. ### W1.16 — Retry-After and timeout identity unreachable through retry wrappers (gated: classification ruling)

`withRetry` hoists `status` onto its `retry_exhausted` AppError (`retries.ts:324-337`) but puts headers only into metadata — so `getErrorHeaders` in hosted-tts-retry and run-mistral-stt silently fall back to default cooldowns for wrapped errors; and the wrapper's name/message hide timeout identity, so `classifyFetchRetry`'s conservative-class timeout policy inverts (a direct TimeoutError is not retried; the same timeout under a wrapper is retried as unclassified). Standalone (the introspection-module consolidation was cut).

### W1.17 — Replicate REST errors skip redaction

`replicate-prediction.ts:33-39,140-148` embeds the unredacted parsed provider payload in AppProviderError metadata and logs; all four sibling clients route through `redactPayloadPreview`. Fix: apply the same redaction + bounded-capture to replicate's error path. Subsumed by W4.7.

### W1.18 — Two contract-test suites run with real API keys present

`voice-quality-report-contracts/shared.ts` and `html-url-backends-contracts/shared.ts` restore env in afterEach but never clear it in beforeEach (both snapshot at module load) — tests inherit the developer's real OPENAI/ASSEMBLYAI/provider keys, the precondition for an accidental paid call if any path escapes the fetch mock. Fix: add per-test snapshot+clear to both (a small semantic change — run each suite before/after). Subsumed by W3.1.

### W1.19 — Concat list file leaks on ffmpeg failure for nine TTS runners

`concatAndConvertToWav` (`audio-utils.ts`) writes `speech-<provider>-chunks.txt` and removes it only on success — the throw at :169 precedes the rm at :172, so all 8 hosted-tts-chunk-pipeline adopters and Mistral leak the file into the output dir on concat failure (only MiniMax's runner-level finally covers it). Tests: generic-selector-normalization pins exact rawArgs arrays and will be rewritten; provider-expansion-concurrency pins occurrence-order-dependent model lists. The parse core touches every command — the harness is the mitigation.
