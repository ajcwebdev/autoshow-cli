# Structural Legacy Program

Date: 2026-08-09. Status: **execution in progress — W1.0 through W1.5 complete.** This is the legacy analog of what `behavioral-consolidation-report.md` was to `duplication-report.md`: where `legacy-report.md` closed the mechanical backlog (dead code, drift, hand-maintained mirrors), this program executes the larger, riskier, more meaningful legacy work — half-finished migrations, persisted-format versioning debt, compatibility seams whose reasons have expired, and policy surfaces with exactly one policy. Thirty-two findings (stable IDs SL-1 through SL-32), all adversarially verified against source, organized into ten waves of atomic subwaves so the program can proceed slowly, one landable change at a time, until complete.

Decisions recorded 2026-08-09, not to be re-litigated:

- **Clean break on persisted formats.** No migration or upgrader machinery is built anywhere in this program. Persisted-format changes ship as version bumps that loudly reject older artifacts with an actionable error; on-disk runs from before a bump becoming non-resumable is accepted. This supersedes `legacy-report.md`'s lesson 2 ("never bump a `schemaVersion` without shipping the upgrader"): the new rule is **never bump without a loud, actionable version error** — silent breakage is the only sin. Comic's existing hard-reject-with-actionable-message policy, previously the outlier, is now the repo-wide pattern.
- **No removal of working functionality or provider-served models.** Removals are confined to dead weight that never worked, provider-dead selectors gated on the provider's own published enumeration, and surfaces provably read or passed by nothing. This rule covers feature surface and models; it explicitly does *not* cover persisted-artifact compatibility, per the clean-break decision above. Under exactly this rule, the whisper CoreML provisioning pipeline is removed (W6.1): its entire output is unloadable by the shipped binary, so there is no functionality in it to preserve.
- The unified structured-output failure envelope is the non-mimicking `{ _raw, _validationError }` shape (W4.1).
- The whole report is slated for implementation. W1.0 received explicit implementation approval and is complete; W3.0 and the refresh ADRs of Wave 9 still stop for their ADR approval per the house convention that plan approval is not implementation approval.

Provenance: eight audit lenses ran in parallel (persisted formats, CLI surface, provider/API, half-migrations, legacy codecs, infra, doc-vs-code drift, dead reachability behind live symbols); every finding was re-verified by an adversarial pass whose default stance was refutation; a completeness critic swept for missed classes. Forty findings were raised, one was excluded for re-litigating a `legacy-report.md` §4 cleared item, and the survivors merged across lenses into the thirty-two here. The verification pass re-proved the prior program's first lesson — confirming an observation never confirms its prescription: four proposals would have made things worse as written. The corrected mechanisms are the ones scheduled below.

The organizing thesis: the prior legacy audit's durable finding was drift; this program's is **format fear**. `schemaVersion` fields are stamped on every persisted artifact, migration machinery exists nowhere, and the standing rule that a bump requires an upgrader meant no bump ever shipped — so persisted-shape evolution froze, and the code accreted overloads, inference heuristics, and two-era vocabularies to avoid touching a single persisted byte. That is how the oldest deferred item in the repo (the `'x-space'` route split, ADR-002) stayed deferred through three audit programs. The clean-break decision dissolves the freeze from the other side: instead of building the upgrader, license the break. Around that center: migrations that shipped the easy half and stopped (comic got the native tokenizer but not native dispatch; credential-catalog derivation landed for two of six steps; ADR-005's endpoint retirement covered write providers but not image/fal; CoreML provisioning shipped without the build flag that would let its output load), and genericity nothing uses (engine unions with one member, options bags with provably no-op fields, 8-way policy spaces exercised 2 ways).

## 1. Execution rules

Each subwave is one atomic change: it lands alone, leaves no half-migrated state, and passes `bun run check` plus the no-cost smoke set (`cli-help-contracts`, `cli-usage-errors`, `option-resolution-contracts/`) plus the suites named inline. Nothing in this program needs a paid or quota-limited provider command to verify; several subwaves touch paid entry points whose contract tests use injected probes and mock fetch — verify through those, never by executing the command. W1.1 discovered one exception to the earlier suite-level assumption: `resume-provider-surface-contracts.test.ts` contains a partial-write path that can reach configured hosted providers, so do not run the entire `resume-manifests/` directory as a no-cost suite; use the three explicitly listed W1.1 files below. Before any removal, re-confirm the call-site enumeration rather than trusting this document; negative-control every new guard by breaking what it claims to catch, restoring, and re-comparing bytes.

Sequencing: Wave 1 is the spine and should complete before its dependents (W1.1 before W1.2/W1.3/W1.4; W8.1 before W9.1; W4.1 before W4.2; W3.1 before W3.2; Wave 10 is gated on Wave 4's results and Wave 9's answers). Waves 2, 4, 5, 6, 7, and 8 are mutually independent and independent of the spine except where noted — they can interleave freely, which is what makes slow, steady execution safe. Within a wave, subwaves are ordered but need not be adjacent in time.

## 5. Wave 4 — structured output

**W4.1 — SL-11: one failure envelope, one retry-policy home.** Structured-output validation failures persist in two divergent unversioned envelopes — compat writes `{ content, _validationError }`, native writes `{ _raw, _validationError }` — and the compat shape perfectly mimics a legitimate freeform success (`FREEFORM_CONTENT_SCHEMA` is `{ content }`), so nothing downstream can tell a validated result from a three-times-failed run: the renderer returns `content` verbatim, the native envelope renders as an accidental "## Raw" document, and `generation-stage-runner` feeds either into paid TTS/image/video/music. Parameterize with `ARG YT_DLP_URL`/`ARG YT_DLP_SHA256` defaulting to the pinned linux values, verify with `sha256sum -c` before chmod, add a two-direction pin test beside `autoshow-docker-wrapper.test.ts` comparing ARG defaults against the resolved dependency metadata (catches future `config/deps.json` overrides too). Trade-off made visible by the pin: container yt-dlp fixes now require a deps bump, moving host and container together. Size S, net ≈ +20.

**W6.5 — SL-23a: atomic rename-takeover for stale-lock reaping.** `removeStaleProcessLock` judges staleness from a read and then unconditionally `rm -rf`s, so with two waiters on a stale lock one can reap the other's freshly-acquired lock — both then hold it. Replace delete-in-place with rename-takeover (rename the lock dir aside, verify the owner is still the stale one, rename back if not), handle the failed-rename-back arm without throwing out of the acquire loop, sweep or ignore orphaned `.reap-*` dirs, and document the residual three-contender window as accepted. Prove it with a **new** two-waiter dead-pid contract test — the existing serialization test's topology cannot exercise this race and proves nothing about the fix in either direction. Size S/M, net ≈ +25.

**W6.6 — SL-23b: fix the actual flake — false staleness.** The known flaky test spawns one holder and one waiter, so W6.5's race cannot be its mechanism; the plausible cause is a CPU-starved live holder's heartbeat lagging past `staleMs`, letting the single waiter reap a live lock. When the owner's hostname matches and its pid is a live process, do not reap on heartbeat age alone — re-read after a grace interval or require a much larger staleness multiple for live-pid same-host owners. Note the flaky test asserts empty stderr, so any new warn on the hot path can itself introduce noise. This closes the one item `legacy-report.md` §1 said still deserved work. Size S. Verify both W6.5/W6.6 with repeated local runs of `process-lock-contracts.test.ts`.
