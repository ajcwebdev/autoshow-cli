# Legacy Programs Archive

This archive combines the completed mechanical legacy audit and the structural legacy program that followed it. Part I preserves the guards, rebuild trails, and settled decisions from the original audit; Part II records the larger structural program and its closure accounting.

## Part I — Legacy and backwards-compatibility audit

Three audits and thirty-five waves, all landed 2026-08-06/07. **Nothing in this part is open.** It is kept for three things: the guards in §2, which are load-bearing and shaped the way they are for reasons worth knowing before editing them; the decisions in §4, which exist so they are not re-litigated; and the rebuild trails in §3 for the two large removals most likely to need reversing.

The durable finding was never the dead code — it was **drift**: hand-maintained lists that silently stopped mirroring their registries, docs prescribing env vars the CLI no longer reads, schemas documenting capabilities never implemented. Dead code is harmless until someone reads it; drift actively misleads. Every user-visible defect these audits found was drift, and §2 is the set of guards that now make each class of it self-detecting.

Three lessons that outlived their waves:

- A `[verified]` mark records that a finding's *observation* was confirmed, never that its *prescription* was. Several findings would have made things worse applied as written — a new dead alias, a regressed warning suppression, a fleet of non-resumable manifests — and roughly a third of the prescribed test retargets turned out to restate something the file already contained verbatim.
- ~~Never bump an artifact `schemaVersion` without shipping the upgrader in the same change.~~ **Superseded 2026-08-09 by ADR-002.** Persisted run artifacts now use clean breaks: a bump ships with a loud, actionable unsupported-version error and no upgrader. Old runs becoming non-resumable is accepted; silently treating them as missing is not.
- Dead *symbols* and dead *reachability behind live symbols* are different classes. Optional parameters no caller passes survive symbol-level sweeps and need per-option call-site enumeration to find, which is why a whole wave of them survived two audits.

### 1. Verification bar

Per change: `bun run check`, then the no-cost smoke set (`cli-help-contracts`, `cli-usage-errors`, `option-resolution-contracts/`). `bun test test/test-cases/validation/` is green at 1266 tests across 186 files; treat any failure as real — the old standing allowance for pre-existing failures was withdrawn 2026-08-07. One known exception, unrelated to any wave: `process-lock-contracts.test.ts`'s "process lock serializes separate processes" is timing-sensitive and flaked three times in eight full-suite runs on 2026-08-07, always passing on immediate re-run. That rate is high enough to be worth fixing rather than tolerating — it is the one thing in this part that arguably still deserves work, though no audit finding raised it. Never run paid-provider commands to verify anything in this part; paid e2e suites cited as pins are read-only citations, not instructions to execute.

Two conventions the waves converged on, worth reusing: re-confirm unreachability by enumerating construction sites and call sites immediately *before* a removal rather than trusting the finding, and negative-control a new guard by breaking the thing it claims to catch, then restoring the file and re-comparing bytes.

### 2. Shipped guards

Each replaced a hand-maintained mirror with a derived source or a two-direction pin. Where a clause below explains *why* a guard is shaped oddly, that clause is the reason it works — check it before simplifying.

- `registry-derived-config-keys.test.ts` — every step-2 registry `configPath` parses under the strict config schema.
- `getHostedProviderEnvKeysForConfigPrefix` — setup's credential catalogs are derived, not typed.
- `help-flag-groups.test.ts` — declared and claimed help groups are equal in both directions. Caught a stale key on its first run.
- `buildConfigPatchFromFlags`'s discarded-flag warning — a flag with no config destination says so instead of succeeding silently.
- `explicit-runtime-exclusions.test.ts` — `RUNTIME_ONLY_FLAGS` stays disjoint from `FLAG_TO_CONFIG_PATH`, with `prompt`'s premise pinned separately.
- `RETIRED_MUSIC_MODEL_RATES` — retiring a priced model means moving its rate to a historical table, not deleting it.
- `links-registry-contracts.test.ts` plus the derived `fixtures/registry.ts` — links fixture expectations are read from the `model-links/*.json` registries at runtime. Accepted residual: expectations and production read the same JSON, so a truncated registry propagates silently. Add a small hand-pinned sentinel only if that becomes credible — a generator writing literal fixtures would be strictly worse, since it reintroduces the on-disk copy that caused the original drift.
- `llm-defaults.test.ts` — every `--llm` provider target has a `FLAG_TO_CONFIG_PATH` entry, so a provider the help advertises cannot silently save nothing.
- `model-selector-messages.test.ts` — every `createModelValidator` key resolves to a public selector, and every provider target round-trips to its own selector. The key list is **collected at construction**, so it cannot be hand-maintained.
- `model-flags-and-ordering.test.ts`'s URL partition pin — `LOCAL_URL_ARTICLE_BACKENDS` and `HOSTED_URL_ARTICLE_BACKENDS` must partition `URL_ARTICLE_BACKENDS`, asserted through `isLocalUrlBackend` **against the hosted list rather than the local one**, so the check cannot restate the implementation.
- `benchmark-contracts.test.ts`'s whisper-probe pin — the probe must call its injected `exists` with exactly `whisperBinaryPath`, imported from the module the whisper *runner* executes. Both arms go through the **injected** probe, so the guard does not depend on whether whisper is installed on the machine running the suite.
- `shipped-fixture-contracts.test.ts` — every path `git ls-files input/` reports must survive `git check-ignore --no-index`. `--no-index` is load-bearing: plain `check-ignore` reports nothing for tracked paths, which is precisely how the old breakage stayed invisible. Two further cases pin `MISTRAL_DEFAULT_REF_AUDIO` as shippable-and-present, and five hypothetical personal-media paths as still ignored — that last one keeps the allowlist from being "simplified" into a glob, and needs no file on disk.
- `image-command-flag-spellings.test.ts` — `imageCommandOptionNames` and the flags the `image` command registers agree in both directions, and every internal spelling retargets to exactly its public one, so **a key that is a prefix of another key cannot silently rewrite it**.
- `prompt-loader-contracts.test.ts`'s preset loop — song-lyric preset coverage runs through `resolveStructuredSchema`, which validates against `preset-registry.ts`, rather than through a lookup that compared a prompt entry's own string to itself.

At the time, the absence of an upgrader blocked the rename. *Benchmarks and fixtures.* The whisper probe stopped looking for a `whisper-cpp` command this project never puts on `PATH` — the practical effect of that bug was that `--stt-services whisper` silently resolved zero services on every machine — and now file-checks `runtime/bin/whisper-cli`. *Guards blessed rather than changed.* The `stt`/`ocr` tombstone in `cli-usage-errors.test.ts` is kept and commented — nothing in the parser reserves those names, so that test **is** the entire reservation, which is what makes deleting it consequential. ## Part II — Structural legacy program

Date: 2026-08-10. Status: **complete — W1.0–W1.5, W2.1–W2.5, W3.0–W3.2, W4.1–W4.3, W5.1–W5.5, W6.1–W6.6, W7.1–W7.3, W8.1–W8.3, W9.1–W9.3, and W10.1 complete.** This program is the structural successor to the mechanical legacy audit in Part I: where Part I closed the mechanical backlog (dead code, drift, hand-maintained mirrors), this program executes the larger, riskier, more meaningful legacy work — half-finished migrations, persisted-format versioning debt, compatibility seams whose reasons have expired, and policy surfaces with exactly one policy. Thirty-two findings (stable IDs SL-1 through SL-32), all adversarially verified against source, organized into ten waves of atomic subwaves so the program could proceed slowly, one landable change at a time, until complete.

Decisions recorded 2026-08-09, not to be re-litigated:

- **Clean break on persisted formats.** No migration or upgrader machinery is built anywhere in this program. Persisted-format changes ship as version bumps that loudly reject older artifacts with an actionable error; on-disk runs from before a bump becoming non-resumable is accepted. This supersedes Part I's lesson 2 ("never bump a `schemaVersion` without shipping the upgrader"): the new rule is **never bump without a loud, actionable version error** — silent breakage is the only sin. Comic's existing hard-reject-with-actionable-message policy, previously the outlier, is now the repo-wide pattern.
- **No removal of working functionality or provider-served models.** Removals are confined to dead weight that never worked, provider-dead selectors gated on the provider's own published enumeration, and surfaces provably read or passed by nothing. This rule covers feature surface and models; it explicitly does *not* cover persisted-artifact compatibility, per the clean-break decision above. Under exactly this rule, the whisper CoreML provisioning pipeline is removed (W6.1): its entire output is unloadable by the shipped binary, so there is no functionality in it to preserve.
- The unified structured-output failure envelope is the non-mimicking `{ _raw, _validationError }` shape (W4.1).
- The whole program received implementation approval and is complete. W10.1's conditional deletion did not occur because MiniMax's published documentation answered its provider-capability gate negatively; preserving the sole live compatibility consumer follows the program's no-removal-of-working-functionality rule.

Provenance: eight audit lenses ran in parallel (persisted formats, CLI surface, provider/API, half-migrations, legacy codecs, infra, doc-vs-code drift, dead reachability behind live symbols); every finding was re-verified by an adversarial pass whose default stance was refutation; a completeness critic swept for missed classes. Forty findings were raised, one was excluded for re-litigating a Part I §4 cleared item, and the survivors merged across lenses into the thirty-two here. The verification pass re-proved the prior program's first lesson — confirming an observation never confirms its prescription: four proposals would have made things worse as written. The corrected mechanisms are the ones scheduled below.

Closure audit 2026-08-10: every stable finding ID from SL-1 through SL-32 is accounted for. SL-12 intentionally spans W4.2 and W10.1, SL-17 spans W5.3 and W5.4, and SL-23 spans W6.5 and W6.6; W1.0, W3.0, and W9.3 are decision or documentation subwaves without separate finding IDs. No scheduled subwave remains open. The final local/no-cost rerun passed `bun run check`, `git diff --check`, the default smoke set (194/194), and the focused closure contracts for Waves 6–10 (164/164). The MiniMax video and structured-output gates and the Google Veo response-shape gate were also rechecked against the cited official primary sources; their retained/pruned outcomes remain supported. Section 14 records only explicitly out-of-scope residuals below this program's bar.

The organizing thesis: the prior legacy audit's durable finding was drift; this program's is **format fear**. `schemaVersion` fields are stamped on every persisted artifact, migration machinery exists nowhere, and the standing rule that a bump requires an upgrader meant no bump ever shipped — so persisted-shape evolution froze, and the code accreted overloads, inference heuristics, and two-era vocabularies to avoid touching a single persisted byte. That is how the oldest deferred item in the repo (the `'x-space'` route split, ADR-002) stayed deferred through three audit programs. The clean-break decision dissolves the freeze from the other side: instead of building the upgrader, license the break. Around that center: migrations that shipped the easy half and stopped (comic got the native tokenizer but not native dispatch; credential-catalog derivation landed for two of six steps; ADR-005's endpoint retirement covered write providers but not image/fal; CoreML provisioning shipped without the build flag that would let its output load), and genericity nothing uses (engine unions with one member, options bags with provably no-op fields, 8-way policy spaces exercised 2 ways).

### 1. Execution rules

Each subwave is one atomic change: it lands alone, leaves no half-migrated state, and passes `bun run check` plus the no-cost smoke set (`cli-help-contracts`, `cli-usage-errors`, `option-resolution-contracts/`) plus the suites named inline. Nothing in this program needs a paid or quota-limited provider command to verify; several subwaves touch paid entry points whose contract tests use injected probes and mock fetch — verify through those, never by executing the command. W1.1 discovered one exception to the earlier suite-level assumption: `resume-provider-surface-contracts.test.ts` contains a partial-write path that can reach configured hosted providers, so do not run the entire `resume-manifests/` directory as a no-cost suite; use the three explicitly listed W1.1 files below. Before any removal, re-confirm the call-site enumeration rather than trusting this document; negative-control every new guard by breaking what it claims to catch, restoring, and re-comparing bytes.

Sequencing: Wave 1 is the spine and should complete before its dependents (W1.1 before W1.2/W1.3/W1.4; W8.1 before W9.1; W4.1 before W4.2; W3.1 before W3.2; Wave 10 is gated on Wave 4's results and Wave 9's answers). Waves 2, 4, 5, 6, 7, and 8 are mutually independent and independent of the spine except where noted — they can interleave freely, which is what makes slow, steady execution safe. Within a wave, subwaves are ordered but need not be adjacent in time.
